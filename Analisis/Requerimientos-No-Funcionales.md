
# 03. Requerimientos no funcionales del sistema SERF

## 1. Introducción

Los requerimientos no funcionales establecen las condiciones de calidad, seguridad, rendimiento y mantenimiento que deberá cumplir el sistema SERF.

## 2. Requerimientos no funcionales

### RNF01. Seguridad
El sistema deberá proteger el acceso mediante autenticación y autorización de usuarios.

### RNF02. Usabilidad
La aplicación deberá contar con una interfaz sencilla, intuitiva y fácil de utilizar.

### RNF03. Disponibilidad
El sistema deberá estar disponible para los usuarios autorizados durante su funcionamiento operativo.

### RNF04. Rendimiento
El sistema deberá responder de manera eficiente a las consultas y operaciones realizadas por los usuarios.

### RNF05. Escalabilidad
La aplicación deberá permitir incorporar nuevas filiales y funcionalidades sin modificar completamente su estructura.

### RNF06. Mantenibilidad
El código deberá organizarse mediante componentes reutilizables, principios SOLID y patrones de diseño.

### RNF07. Compatibilidad
La aplicación deberá poder utilizarse desde navegadores web modernos en computadoras y dispositivos móviles.

### RNF08. Integridad de datos
El sistema deberá validar la información registrada para evitar inconsistencias en ventas e inventarios.

### RNF09. Estandarización
Los reportes deberán mantener formatos y criterios corporativos uniformes.

### RNF10. Configurabilidad
La aplicación deberá permitir administrar parámetros generales desde una configuración centralizada.

## 3. Resultado esperado

El cumplimiento de estos requerimientos permitirá desarrollar una aplicación segura, mantenible, escalable y accesible para las diferentes filiales de FinanCorp S.A.
